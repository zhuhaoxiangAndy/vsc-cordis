新增

  - create：生成插件骨架（目标目录存在则**拒绝覆盖**；--trust untrusted 会附隔离限制说明）
  - list：列出插件并做依赖图检查（坏清单只影响它自己）
  - tree [--mermaid]：服务依赖图，文本视图 + Mermaid flowchart

- packages/cli/src/graph.ts：**纯函数**依赖图核心（无 IO），检测缺提供者 / 多提供者 /
  依赖环 / 隔离插件声明服务 / 版本提示，并给出拓扑加载顺序。
- plugin.json 新增 `provides` 声明；内核校验；宿主激活后比对声明与实际并**告警**。

为什么需要 provides
服务是运行期 ctx.provide() 注册的，清单里原本只有 dependencies（我需要什么），
没有"我会提供什么" —— 静态依赖图根本画不出来。

关键决策（ADR-0014）
- `provides` **只服务工具**：不参与任何加载决策；声明与实际不符**不会**导致加载失败，
  但宿主会告警。取这个中间态的理由：不检查会重演 CordisPlugin.inject 那个坑
  （声明了却不生效且无反馈），而阻断会把纯工具字段变成加载门槛。
- 静态图的硬边界写进 CLI 输出本身：服务**版本**由运行期 ctx.provide({version}) 决定，
  清单里没有这个概念，所以图只能校验"有没有提供者"；隔离插件不参与服务依赖。
- CLI **复用**而非复制：discovery 与 integrity 都从 host 包相对导入，保证只有一份实现。
  代价写清：CLI 无法脱离本 monorepo 单独发布（它是 private 的内部工具）。
- 退出码 0/1/2，于是 `vscordis list` 可以直接进 CI。
