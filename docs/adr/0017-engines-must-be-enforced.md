# ADR-0017：`engines` 必须被强制，不能被静默丢弃

状态：已接受（2026-02-14，收尾轮）｜决策者：无人值守自主决策

## 背景：这是同一个陷阱的第三次出现

排查"还有哪些字段声明了却不生效"时发现：`plugin.json` 的 `engines` 字段
**在 SDK 类型里有、在 `validateManifest` 里根本没被读** ——
也就是说它会被归一化过程静默丢掉，作者写了等于没写，而且没有任何反馈。

前两次是：

| 字段 | 当时的问题 | 处理 | ADR |
| --- | --- | --- | --- |
| `CordisPlugin.inject` | 声明了但依赖解析只读 `plugin.json` | 真正接入解析（两道判定） | 0010 |
| `provides` | 声明了但无人校验与实际是否一致 | 激活后比对并**告警** | 0014 |
| `engines` | **校验器压根没读，字段被丢弃** | 结构校验 + 激活前**强制** | 本 ADR |

## 决策 1：先归一化（读取 + 结构校验），再强制（兼容性）

- `NormalizedManifest` 新增 `engines?: { vscordis?: string; vscode?: string }`；
- 非对象、或版本范围不在支持子集内（`*` / `x.y.z` / `^x.y.z` / `>=x.y.z`）→ **拒绝加载**（fail-closed，
  与 `dependencies` 的版本范围处理一致）；
- 空对象归一化成 `undefined`，避免"看起来声明了"的假象。

## 决策 2：兼容性检查放在 `#activate` 的**最前面**，且在 `loadModule` 之前

理由与完整性校验一致（ADR-0012）：不兼容的插件连模块都**不该被求值**。
测试专门断言 `port.moduleLoads` 为空 —— 只断言"load 抛错"是不够的，
因为抛错可能发生在模块已经跑过之后。

## 决策 3：缺少版本信息时**跳过但留痕**，而不是静默跳过

`PluginHostOptions.hostVersion` / `vscodeVersion` 是可选的（测试与 CLI 可以不传）。
但只要插件声明了 engines 而调用方没给版本，就会记一条 `debug` 日志。

这条规则来自本项目的通用原则：**没有检查必须有理由，而有理由必须留痕**。
静默跳过与静默通过在使用者眼里没有区别，都会让人以为"这个字段被检查过了"。

## 决策 4：版本号先做宽松归一化

`semver-mini` 只认 `x.y.z`，而宿主与编辑器版本常带后缀（`0.1.0-beta.3`、`1.107.1-insider`）。
不归一化的话，一个 `>=0.1.0` 的**合法**声明会在预发布版本上假失败 ——
把"版本不兼容"误报成"插件有问题"是更糟的失败方向。所以先去掉 `-prerelease` / `+build` 再比较。

## 决策 5：顺带修掉一个状态不一致（由本轮测试逼出）

引擎检查原本在 `#activate` 的 try 块**之外**抛出，于是记录停在 `idle` ——
状态面板会把它显示成"从未加载过"，而不是"加载失败"。

现在 `load()` 会兜住这类失败并统一标记 `failed`：
**任何加载失败都必须留下可诊断的 failed 状态**，否则用户看到的是"这个插件好像没被加载过"，
而真正的原因（版本不兼容）只在那一刻的错误提示里出现过一次。

## 未覆盖

- CLI 的 `list` / `tree` **没有**做引擎兼容性检查（它们不读宿主版本）。
  加载期的强制已经能拦住，CLI 的问题只是"不够提前"。要补的话应当读
  `packages/host/package.json` 的版本 —— 那会给 CLI 增加一层对宿主包的耦合，暂不做。
- `engines.vscode` 用的是**我们自己的**范围子集，与 VSCode 官方扩展清单的 `engines.vscode`
  语义不完全相同（官方支持 `^1.95.0` 这类，但也接受更宽的写法）。这里刻意保持最小区集，
  并在清单校验期对超出子集的写法**报错**，而不是猜测作者意图。
