# ADR-0016：隔离能力的取舍 —— 配置快照与状态栏项，以及**为什么不假装支持**事件与服务

状态：已接受（2026-02-14，M4c 轮）｜决策者：无人值守自主决策

## 背景

ADR-0013 决策 5 把隔离模式的能力收窄到"命令 + 消息 + 输出通道 + 工作区快照"，
并把 `createStatusBarItem` / `getConfiguration` / `onDidSaveTextDocument` / 服务留作 M4c。
本 ADR 决定补哪些、不补哪些，以及**为什么理由比进度更重要**。

## 统一的判据：这个 API 的**类型契约**能不能在跨进程下被诚实履行？

| 能力 | 类型契约 | 跨进程能诚实履行吗 | 结论 |
| --- | --- | --- | --- |
| `getConfiguration().get()` | **同步**返回任意值 | 能：宿主预取 + 变化推送，子进程读本地缓存 | ✅ 补 |
| 状态栏项（属性读写） | 属性读回是**同步**的 | 能：本地镜像；写入是 UI 副作用，本身就不需要回执 | ✅ 补 |
| `onDidSaveTextDocument` | 回调参数是 `TextDocument`，带 `getText()` 等**同步方法** | **不能**：跨进程只能传纯数据子集 | ❌ 不补 |
| `ctx.use(name)` | 返回带方法的**进程内对象**，`clock.now()` 返回 `Date` | **不能**：代理会让它变成 `Promise<Date>` | ❌ 不补 |

表里最后两行的关键不是"工程量"，而是：**要支持它们，同一份插件代码在两种模式下就不能长一样了**。
而"写法一致、差异只在运行时边界"是隔离方案能被插件作者接受的前提。

## 决策 1：配置 —— 声明式预取 + 变化推送，而不是"子进程按需查询"

```
plugin.json:  configuration: { section: "my-plugin", keys: ["greeting"] }
                │
       激活时按 keys 预取（键用全限定名 section.key）
                ▼
       子进程本地缓存 ←── 配置变化时宿主主动推送（configChanged）
                │
       插件侧 get(key, default) 读缓存 —— 全程同步
```

- 为什么不"子进程去问宿主"：那只能返回 Promise，直接违背 `get()` 的同步契约。
- 为什么要有**推送**（而不只是激活时快照）：快照会陈旧 ——
  插件在命令里读配置是很常见的写法，读到旧值就是 bug。推送让二者兼得。
- 代价：**未声明的键拿不到值**，只能回落默认值，并**告警一次**。
  这是刻意的取舍：声明是"我要读这些"，不声明就没有办法预取。
- 写配置（`update()`）在隔离模式下**抛错**：写操作需要宿主代为执行且要过 `config.write` 权限，
  本轮不做，但错误信息会说明原因和替代方案。

## 决策 2：状态栏项 —— 本地镜像 + **串行** RPC

三个细节，每一个都对应一类真实 bug：

1. **本地镜像**：`item.text = 'x'` 之后 `item.text` 必须立刻读回 `'x'`。
   若每次都去问宿主，读属性就变成异步的 —— 又成了假接口。
2. **串行队列**（而不是各自 fire-and-forget）：`item.text = 'x'; item.show()` 必须按顺序到达宿主，
   否则会出现"状态栏显示了，但文字还是旧的"。用一条 promise 链，不用两个独立的 `void call(...)`。
3. **未支持的属性用 Proxy 响亮拒绝**：普通对象对 `item.backgroundColor = 'red'` 是**静默接受**的
   （不改 UI 也不报错）。日志里什么都没有的"设置没生效"是最难查的一类问题，所以直接抛错并列出支持集合。

写入本身是 fire-and-forget 语义 —— 这与 VSCode 自己一致（设置状态栏文字不需要等 UI 确认）。
但**顺序**必须保，见第 2 点。

## 决策 3：不支持的能力，理由必须是**真实原因**，不是"还没做"

`ISOLATION_UNSUPPORTED` 的文案从"属于 M4c 的范围"改成了：

- 事件订阅 → "类型契约会撒谎：回调参数带同步方法，跨进程只能给纯数据子集"；
- 服务 → "服务是带方法的进程内对象，代理会让 `clock.now()` 从 `Date` 变成 `Promise<Date>`，
  于是插件代码在两种模式下就不是同一份了"。

两处都指向本 ADR，而不是指向一个待办清单。理由：

- "还没做"会让读者以为**等一等就能用**，于是按隔离模式设计插件时会做出错误假设；
- 真实原因会告诉读者**该换哪条路**（改用 `trust: trusted`，或改用数据快照式设计）。

测试也相应改成断言**实质理由**（`/类型契约会撒谎/`、`/同步方法/`），而不是断言待办编号。
理由集中在协议层一处定义，避免两处说法漂移。

## 实现细节（值得记下的小坑）

- 配置快照的键用**全限定名**（`section.key`）：子进程无法可靠地拼出宿主侧的 section，
  由宿主统一拼好，子进程只管查表。
- `statusBar.update` 的 patch 用 `'accessibilityInformation' in raw` 判断而不是
  `!== undefined` —— 后者无法表达"把它设回 undefined"。
- 状态栏项句柄与输出通道句柄一样做**归属校验**：猜一个数字不能写到别人的项上。

## 未覆盖

- 配置只支持**读**；`config.write` 在隔离模式下未实现。
- 状态栏项支持 `text / tooltip / command / color / name / accessibilityInformation` 与
  `show / hide / dispose`；`backgroundColor`（已废弃）会响亮抛错。alignment/priority 只在创建时生效。
- 事件与服务**永久**不在隔离模式的支持范围内（除非引入一套独立的、显式异步的 API 面）——
  那是一个产品决策，不只是实现工作。
