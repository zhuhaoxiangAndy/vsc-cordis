# ADR-0011：热重载（M3）的边界与失败语义

状态：已接受（2026-02-14，M3 实施轮）｜决策者：无人值守自主决策

## 背景

目标是"改一个插件的源码，<1 秒内在不重启 VSCode 的前提下生效"。
这件事被拆成两段，且两段的归属必须明确，否则很容易把编译器塞进运行时。

## 决策 1：编译归开发期，监听归运行时

```
源码改动 ──(esbuild --watch，scripts/watch.mjs)──► dist/index.cjs
                                                      │
                                          (PluginWatcher，fs.watch)
                                                      ▼
                                          planReload → PluginHost.reload
```

否决方案：**把 esbuild 作为宿主扩展的运行时依赖**。理由：编译是开发期动作；
把它打进 `dist/extension.cjs` 会显著增加发布体积与启动开销，而 `npm run watch`
只需要在终端里多开一个进程。代价是开发者必须记得开 watch —— 因此
`npm run watch` 与 README 都要显式写明，且热重载失败时日志要能指出"dist 没有更新"。

## 决策 2：`planReload` 是纯函数，`PluginWatcher` 只是 fs 适配层

"哪些文件变了 → 该重载谁"的判定全部收进无 IO 的 `planReload(changedPaths, roots)`，
于是可以用单测穷举边界（噪声文件、根外文件、根目录下的散落文件、清单变更……），
而 `PluginWatcher` 只负责 `fs.watch` + 防抖聚合。

两条细则：

- **`plugin.json` 变更必须升级为"重新扫描"**，而不只是重载：id / 依赖 / 权限都可能变，
  这些会影响"算不算同一个插件"。只 reload 会得到与清单不一致的运行状态。
- **无法定位的变化（`filename === null`）也升级为重新扫描**：宁可多扫一次，不要漏掉一次变更。

## 决策 3：`fs.watch({ recursive: true })` 而不是 VSCode 的 FileSystemWatcher

- 插件根可以位于 `globalStorage`（工作区之外），VSCode 的 watcher 需要 RelativePattern 包装，且
  受工作区信任与文件排除配置影响；
- `fs.watch` 的递归模式在 Node ≥22.18 上三大平台都可用（本仓库 engines 已是 `>=22.18`）；
- 用 `persistent: false`：监听器不该自己把进程吊住（测试环境需要，扩展宿主里事件循环本来就活着）。

代价：`fs.watch` 在不同平台上的事件粒度不一致（可能重复、可能只报目录）。
因此**所有事件都只是"提示"**，真正的判定交给 `planReload` 与后续的重载逻辑，
重复事件最多导致一次多余的重载，不会导致状态错误。

## 决策 4：重载 = 完整 unload + load，不做"原地替换"

沿用 ADR-0007 决策 4 的粒度。理由：VSCode 的命令/监听器注册表是全局的，
"原地替换"意味着要把旧命令的热替换与失败回滚做对 —— 而失败回滚需要"双份同时在线"的能力，
在扩展宿主里代价过高。

## 决策 5：热重载失败**可见且不回滚**

新版本 `activate` 失败时：回滚已产生的副作用 → 插件进入 `failed` → **弹出警告 + 写日志**，
但**不**自动切回上一个可用版本。

理由：自动回滚需要把旧版本模块与旧状态同时保活（双份加载），
这会让"无残留"这条核心不变式变得无法断言。
"失败可见 + 用户手动修"比"看起来还在跑但其实是旧版本"更诚实。
这也是为什么失败**不自动重试**（避免错误风暴）。

## 决策 6：删除插件目录 → 卸载

`planReload` 报出的目录若已不存在，且它此前映射过某个插件 id，则卸载该插件。
保守起见只在"目录确实不存在"时才这么做，避免一次瞬时 IO 失败把全部插件卸掉。

## 决策 7：删除 `plugin.json`（目录仍在）→ 卸载旧 incarnation

如果变更目录还在、但 `plugin.json` 已被删除（重命名/移走），旧插件不能继续 active：
"清单已不存在但代码还在跑"会让"无残留"无法解释。判定同样保守：**只有确认文件不存在**
才卸载；文件存在但解析失败时保持旧版本，避免编辑器"先截断再写入"之间的瞬时空窗误卸载。
目录本身被删除继续走决策 6。

## 未覆盖

- **热重载的端到端时延未在真实 VSCode 中测量**（用户决策不跑 e2e）。
  本仓库提供的可验证证据是：`planReload` 的完整单测 + 一次真实 `fs.watch` 集成测试
  （写入新 `dist/index.cjs` → 触发计划 → 重载拿到新模块实例）。
  时延预算的构成（防抖 150ms + esbuild 增量 50–150ms + 重载 10–50ms）写在验收文档里，
  真实数字需要 F5 手动测量。
